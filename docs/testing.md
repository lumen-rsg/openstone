# Testing and reference data

Build and run the suite with the [README commands](../README.md#build). A desktop build adds Qt persistence, importer, settings, and Ruby tests. Ruby tests report a CTest skip when no Ruby runtime is available. Enabling `OPENSTONE_ENABLE_LLVM_ORC` exercises the interpreter and LLVM ORC in the DSP regression tests.

## Public fixtures

The repository includes OpenStone-authored DSP/Assembler probes, generated data, and numeric traces captured for compatibility checks. Their provenance, input sequences, expected outputs, and remaining uncertainty are documented in [the fixture notes](../tests/fixtures/flowstone/README.md).

Extracted FlowStone source is omitted from publication. The 70 omitted files are listed in [external-sources.txt](../tests/fixtures/flowstone/external-sources.txt); [external-sources.json](../tests/fixtures/flowstone/external-sources.json) records source locations, normalized hashes, and derived wrappers. These manifests contain metadata, not the source bodies. The omitted files are ignored by Git so a local private corpus can coexist with the public checkout.

Tests with both authored and private-corpus cases continue running their authored cases. Private-source subchecks print `SKIP private FlowStone reference` when the corpus is absent. They are not evidence of native parity in a public-only run. Set `OPENSTONE_REQUIRE_FLOWSTONE_FIXTURES=1` to treat an incomplete corpus as a failure when running a private reference suite. Supplying reference files is optional, and requires your own lawful access; OpenStone does not download them.

## Compile audit

The optional audit target needs Python 3.9 or newer:

```sh
cmake -S . -B build/audit -G Ninja \
  -DOPENSTONE_BUILD_DESKTOP=OFF \
  -DOPENSTONE_BUILD_ASSEMBLER_AUDIT=ON
cmake --build build/audit --parallel
ctest --test-dir build/audit --output-on-failure
```

The audit's extraction and authored compiler tests run without vendor material. Checks against omitted source files are individually skipped. The [saved audit reports](compatibility/flowstone-assembler-audit.md) describe a separately supplied native corpus; compilation success does not establish numerical parity.

To audit an installed reference build yourself:

```sh
python3 tools/audit_flowstone_assembler.py \
  --flowstone-root /path/to/FlowStone \
  --probe build/audit/openstone_assembler_probe \
  --output /path/outside/checkout/assembler-audit
```

Do not commit extracted sources or vendor distributions. Use an output directory outside the public checkout for private research artifacts.

## Bundled schematic import

A desktop build can optionally test an independently supplied FlowStone Alpha build 5483:

```sh
cmake -S . -B build -DOPENSTONE_FLOWSTONE_ROOT=/path/to/FlowStone
cmake --build build --parallel
ctest --test-dir build -R flowstone_bundled_import --output-on-failure
```

Without this option, the self-contained importer tests still run. The full bundled-module test is not registered. Converted module files generated by private tests stay in the ignored build directory.
