# Assembler audit findings

Snapshot: 2026-11-22, unpacked FlowStone Alpha 5483, OpenStone on macOS ARM64 with LLVM ORC enabled. See the [generated report](flowstone-assembler-audit.md), [CSV](flowstone-assembler-audit.csv), and [full manifest](flowstone-assembler-audit.json) for hashes, exact offsets and diagnostics. These results check compilation and runtime preparation only. They do not replace the saved numerical comparisons or Windows x64 community testing.

## Bundled modules

All 145 `.hom` files were scanned. The extractor recovered 36 Assembler instances in 13 module files, representing 11 distinct sources. All eleven sources compile unchanged and prepare successfully for both the interpreter and LLVM ORC. The Assembler starter snippet also passes both.

**Denormal Remover (Bitmask)**, source `0ad7e57ac1dc`, now passes unchanged.
Its incoming `xmm1` uses an explicit raw register bank, with OpenStone's documented
zero fallback when unbound. Both saved native entry traces are replayed through
the API against the unchanged source in the interpreter and LLVM ORC. This fixes
loading without rewriting `por` or assuming that native FlowStone scratch values
are always zero. [Entry policy and validation](flowstone-assembler-xmm-entry.md).

## Additional executable sources

The executable scan recovered 19 distinct serialized Assembler sources, with 68 occurrences across x86 and x64. All nineteen compile and prepare in both backends. It also found 205 distinct assembly-like null-terminated strings, with 300 occurrences; 36 pass the frontend; 28 prepare in both backends. The other eight require explicit named `__const` resources. The latter category includes full kernels, fragments, templates and engine glue. Its failures are not a count of unsupported standalone modules.

There are 236 category/source entries and 231 distinct source hashes overall. Of 67 frontend-accepted entries, 59 prepare in the interpreter and compile through LLVM ORC; eight are reported separately as `engine-bindings-required`. No additional backend-only failure was observed in this corpus. Shared sources can appear in more than one category.

## Audit tooling

Enable `OPENSTONE_BUILD_ASSEMBLER_AUDIT` to build `openstone_assembler_probe`. The Python driver extracts the corpus, invokes the real frontend, activates every declared output and prepares both backend variants without executing stage 0 or rendering. Every unique source runs in an isolated process with a timeout. Missing LLVM support is reported as unavailable, never as a successful ORC result.

The nineteen audit tests cover stored lengths and source offsets, unchanged CRLF and compatibility headers, malformed records, comma-separated connector counts, zero-count embedded copies, exact deduplication, comment/label handling, unavailable backends, compiler diagnostics, unchanged stage-directive kernels, explicit versus unused engine-binding requirements, unchanged pointer-cell kernels, buffer-transfer caller contracts, unchanged writable-input envelopes, compact-stage caller contracts, numeric Mem descriptor aliases, complete reader and writer caller contracts, x87 conversion caller buffers, scalar memory-destination forms, and report generation. The generated manifest records hashes of the probe, compiler implementation (including the public DSP/runtime fault headers) and every scanned input file. `--extract-dir` retains the recovered source locally; the repository report contains identifiers and diagnostic excerpts rather than redistributing the FlowStone package.
